# Room migration (Phase 4 of 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the SQLDelight tile cache with Room KMP — same two tables, same seven queries, same cache-first semantics, one persistence framework in the app afterwards.

**Architecture:** Room 2.8.4 (last stable 2.x, full KMP: android/ios/jvm) with `BundledSQLiteDriver`, entities/DAO/@Database in `commonMain`, `@ConstructedBy` expect-object per the official KMP pattern. The generated class keeps the name `ChargeSiteDatabase` in `de.autoapp.shared.db`, so `TiledSiteRepository` and `OperatorCatalog` keep their imports. The platform seam `DatabaseDriverFactory` becomes `DatabaseFactory` returning a `RoomDatabase.Builder` ("driver" is SQLDelight vocabulary). Room 3.0 is deliberately NOT used: alpha, new coordinates, breaking — wrong risk for a release app; the 2.8→3 move is a coordinate swap later.

**Data migration: none, deliberately.** Room cannot adopt a SQLDelight-created file (no `room_master_table` identity); faking one is risk without payoff for a cache whose TTL is 3 days anyway. New file `charge_sites.room.db`, version 1, `exportSchema = false` (same philosophy as SQLDelight's `verifyMigrations` off — future migrations get hand-written `Migration` objects plus a hand-written test, exactly like `1.sqm` had). The Android actual deletes the old `charge_sites.db` so no multi-MB corpse survives. Cost: one refetch per area after the update — once. `ChargeSiteMigrationTest` and `1.sqm` go with the stack they tested.

**Tech Stack:** `androidx.room:room-runtime` + `room-compiler` 2.8.4, `androidx.sqlite:sqlite-bundled` 2.6.1, KSP 2.3.11 (`com.google.devtools.ksp`). Version pairs verified empirically at first build; fallbacks: sqlite version per Room 2.8.4's POM, KSP per its releases page if 2.3.11 mismatches Kotlin 2.4.10.

**Spec:** plans/technical-debts.md "Use Room for database access", explicitly confirmed by Raphael against the review's counter-recommendation ("Do Room anyway"). Branch `debt/room` off `debt/navigation3`.

- [ ] **Step 3: ChargeSiteDatabase.kt** — schema transliterated from ChargeSites.sq, comments carried over:

```kotlin
package de.autoapp.shared.db

import androidx.room.ConstructedBy
import androidx.room.Dao
import androidx.room.Database
import androidx.room.Entity
import androidx.room.Index
import androidx.room.Insert
import androidx.room.OnConflictStrategy
import androidx.room.PrimaryKey
import androidx.room.Query
import androidx.room.RoomDatabase
import androidx.room.RoomDatabaseConstructor
import androidx.room.Transaction

// Charging-station local store, and the question of which area was fetched
// when. Two tables, because there are two questions: WHAT do we know
// (chargeSite) and FOR WHAT do we know that we know it completely
// (tileCoverage). Without the second, there'd be no way to tell whether an
// area has no charging station or whether nobody has ever checked there.

@Entity(tableName = "chargeSite", indices = [Index("lat", "lon")])
data class ChargeSiteEntity(
    @PrimaryKey val id: String,
    val sourceId: String,
    val name: String,
    val operator: String?,
    val lat: Double,
    val lon: Double,
    // Connectors as a "type:kW:count" list. A dedicated table would be
    // cleaner, but connectors are never queried on their own — a join for
    // that would be effort without payoff.
    val connectors: String,
    val street: String?,
    val postalCode: String?,
    val town: String?,
)

@Entity(tableName = "tileCoverage", primaryKeys = ["sourceId", "tileLat", "tileLon"])
data class TileCoverageEntity(
    val sourceId: String,
    // Tile indices on a 0.1° grid: floor(degree * 10).
    val tileLat: Long,
    val tileLon: Long,
    val fetchedAtMillis: Long,
)

data class OperatorCount(val operator: String?, val sites: Long)

@Dao
interface ChargeSiteDao {

    @Query("SELECT * FROM chargeSite WHERE lat BETWEEN :south AND :north AND lon BETWEEN :west AND :east")
    suspend fun sitesInBox(south: Double, north: Double, west: Double, east: Double): List<ChargeSiteEntity>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun upsertSites(sites: List<ChargeSiteEntity>)

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun markTilesFetched(tiles: List<TileCoverageEntity>)

    /** One fetch, one transaction: sites and their coverage land together or not at all. */
    @Transaction
    suspend fun recordFetch(sites: List<ChargeSiteEntity>, tiles: List<TileCoverageEntity>) {
        upsertSites(sites)
        markTilesFetched(tiles)
    }

    // Tiles of the area that are fresh enough. The caller compares the count
    // against the number of requested tiles: if one is missing, it refetches.
    @Query(
        "SELECT count(*) FROM tileCoverage WHERE sourceId = :sourceId " +
            "AND tileLat BETWEEN :minTileLat AND :maxTileLat " +
            "AND tileLon BETWEEN :minTileLon AND :maxTileLon " +
            "AND fetchedAtMillis > :notOlderThanMillis",
    )
    suspend fun freshTileCount(
        sourceId: String,
        minTileLat: Long,
        maxTileLat: Long,
        minTileLon: Long,
        maxTileLon: Long,
        notOlderThanMillis: Long,
    ): Long

    /** Discards coverage, not the sites themselves: the store stays readable. */
    @Query("DELETE FROM tileCoverage WHERE sourceId = :sourceId")
    suspend fun clearCoverage(sourceId: String)

    @Query("DELETE FROM chargeSite")
    suspend fun clearAll()

    // The networks picker wants its list before the first live fetch: what
    // the store already knows is good enough to seed it.
    @Query("SELECT operator, COUNT(*) AS sites FROM chargeSite WHERE operator IS NOT NULL GROUP BY operator")
    suspend fun operatorCounts(): List<OperatorCount>
}

// exportSchema = false for the same reason verifyMigrations was off under
// SQLDelight: a schema snapshot per version costs more than it buys at one
// migration so far. A future schema change gets a hand-written Migration
// plus a test, like 1.sqm had.
@Database(entities = [ChargeSiteEntity::class, TileCoverageEntity::class], version = 1, exportSchema = false)
@ConstructedBy(ChargeSiteDatabaseConstructor::class)
abstract class ChargeSiteDatabase : RoomDatabase() {
    abstract fun chargeSites(): ChargeSiteDao
}

// The actuals are generated by Room's KSP — this is the documented KMP pattern.
@Suppress("KotlinNoActualForExpect", "EXPECT_ACTUAL_CLASSIFIERS_ARE_IN_BETA_WARNING")
expect object ChargeSiteDatabaseConstructor : RoomDatabaseConstructor<ChargeSiteDatabase> {
    override fun initialize(): ChargeSiteDatabase
}
```

- [ ] **Step 4: DatabaseFactory.kt (commonMain)**

```kotlin
package de.autoapp.shared.db

import androidx.room.RoomDatabase
import androidx.sqlite.driver.bundled.BundledSQLiteDriver
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.IO

/**
 * Room builds per platform: Android needs a Context for the database path,
 * iOS and JVM don't. The bundled driver keeps the SQLite version identical
 * on every platform.
 */
expect class DatabaseFactory {
    fun builder(): RoomDatabase.Builder<ChargeSiteDatabase>
}

fun createChargeSiteDatabase(factory: DatabaseFactory): ChargeSiteDatabase =
    factory.builder()
        .setDriver(BundledSQLiteDriver())
        .setQueryCoroutineContext(Dispatchers.IO)
        .build()

/** Database file name. The same on every platform; `.room.` because Room
 *  cannot adopt the SQLDelight file this replaces. */
const val CHARGE_SITE_DATABASE_NAME = "charge_sites.room.db"
```

(`kotlinx.coroutines.IO` import shape is empirical — if `Dispatchers.IO` doesn't resolve in commonMain, fall back to `Dispatchers.Default` with a comment.)

- [ ] **Step 5: the three actuals.**

androidMain:
```kotlin
actual class DatabaseFactory(private val context: Context) {
    actual fun builder(): RoomDatabase.Builder<ChargeSiteDatabase> {
        val app = context.applicationContext
        // The SQLDelight-era file — Room can't adopt it, so don't leave a
        // multi-MB corpse in every updated install.
        app.getDatabasePath("charge_sites.db").delete()
        return Room.databaseBuilder<ChargeSiteDatabase>(
            context = app,
            name = app.getDatabasePath(CHARGE_SITE_DATABASE_NAME).absolutePath,
        )
    }
}
```

iosMain (documents directory, per the official KMP setup):
```kotlin
actual class DatabaseFactory {
    actual fun builder(): RoomDatabase.Builder<ChargeSiteDatabase> {
        val documents = NSSearchPathForDirectoriesInDomains(
            NSDocumentDirectory, NSUserDomainMask, true,
        ).first() as String
        return Room.databaseBuilder<ChargeSiteDatabase>(name = "$documents/$CHARGE_SITE_DATABASE_NAME")
    }
}
```

jvmMain (tests only, in-memory):

        Room.inMemoryDatabaseBuilder<ChargeSiteDatabase>()
